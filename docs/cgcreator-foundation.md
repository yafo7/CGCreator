# CGCreator 基础演出闭环（V2）

## 范围

V2 在原 WorldForge 基线上增加行为优先的 CG 管线。现有 `DirectorDocument.actions` 是唯一的高层行为意图，扩展 route、sit、dialogue、hold；`CompiledCG.performance` 是求解后的事件和占用记录，不维护另一份可编辑行为副本。镜头仍保留稳定 shots ID，用 behaviorId 关联行为。V1 文档与旧 confirmed 保持原采样语义。

`plan → 冻结资源 → 验证行为 → 选择镜头覆盖 → 几何求解 → Preview → Confirm`

新的 AI 规划默认输出 schemaVersion 2 和 actions。首次规划允许 shots 为空，由 `createBehaviorCoverage` 建立稳定的覆盖槽位。`coveragePending` 只控制首次镜头阶段；编译服务先求解实际路线、姿态和接触，成功后才向导演发送 `performanceForDirector`、镜头能力和世界语义。镜头回复只能修改现有镜头的构图/技能/目的，不能修改行为、时间、坐标和硬约束。后续普通编译不重复调用 AI 选择镜头。

## 共享姿态

`cgPoseEvaluator.ts` 的 `sampleLocalPose` 同时用于服务端和客户端。加性 XYZ、绝对四元数和局部缩放遵循已有 baked 约定。`buildPoseRig/evaluateRig` 组合父子矩阵和冻结的模型归一化偏移，返回动态部件位置。V2 的眼睛、脸部、头部和接触点随动画变化。固定摄影机位置可以使用 aimMode:follow 跟随注视，独立于位置轨迹。

姿态箱体对 box 模型是直接几何，对其他模型是保守局部边界。复杂着色器变形、透明折射、蒙皮网格逐三角形证明不在本版保证范围内。

## 路线和支撑面

move.route 指定 guideIds、required/preferred、walk/run 和可选 maxSpeed。required 检查角色半径收缩后的道路走廊；guideIds 描述允许使用的道路集合，精确有序途经点仍由 action-route 硬约束表达。导航禁止直接在水底行走。地形之外，基础后端支持明确命名的水平或缓斜 box 支撑面（floor/deck/platform/step 等），以及 0.26 米以内的支撑转换，不把任意屋顶或座面猜成地板。

路径记录实际 XYZ 和 surfaceIds。平坦安全路径可平滑，平滑后再次验证道路和碰撞。非平坦支撑转换保留求解路径，不重新投影回地形。该后端是有界确定性搜索，不承诺任意复杂多层场景的导航完备性；不支持的表面返回不可达。

道路移动需要实际 clipId。具有 locomotion 元数据的动作按路径速度计算播放速率并检查允许范围。缺少标称速度时会提示需检查步态匹配，不宣称实现通用足部 IK。

## 坐下契约

sit 必须包含 clipId 和 interaction:{objectId,seatNodeId,approachAnchorId}。角色先到达接近点；座椅必须静止，座面必须是有 seat 语义的水平 box。动作必须与当前模型哈希、角色、时长匹配且不循环。

角色模型可通过 `_meta.cgRig` 提供版本化的接触绑定：

```json
{
  "version": 1,
  "landmarks": {
    "hips": {"nodeId":"hips","point":[0,-0.17,0]},
    "leftFoot": {"nodeId":"left_foot","point":[0,-0.04,0]},
    "rightFoot": {"nodeId":"right_foot","point":[0,-0.04,0]},
    "eyes": {"nodeId":"head","point":[0,0.055,0.15]}
  }
}
```

数值仅属于内置校准模型，不可复制到任意模型。point 是节点局部坐标；hips 表示坐姿支撑接触标记，不是简单使用模型原点。

求解器反算根姿态，检查座面尺寸、身体接触、双脚支撑、入座过程与椅子各部件/周边物体的碰撞。接触误差容差 0.035 米，最终脚部支撑容差 0.06 米。30Hz 入座姿态检查和10Hz实体间保守边界检查是有限采样验证。占用从交互开始持续到演出结束，同座位冲突不能确认。坐下结束后保存最后姿态；任意 seek 都重建该状态，不恢复站姿。

基础版不提供站起、移动座椅、通用 IK、任意角色自动绑定。缺少 cgRig 或动作不适配时必须返回明确诊断。dialogue 目前表示参与者与朝向的对话表演，不生成语音或口型。

## 计算式镜头观察

`cgVisibility.ts` 使用实际时刻的根/节点矩阵构建方向包围盒及空间树，裁剪到完整视锥，计算屏幕范围、采样可见率、可见部件、眼睛等语义点的遮挡。包含地形与房间墙体遮挡。透明度为零的部件不参与观察，半透明部件不作为不透明遮挡物。

这不是识图；coverage 是投影边界覆盖率，不是像素掩码面积。观察精度随结果返回。特写还检查眼睛可见与面部朝向；contact 镜头要求座椅进入有效视野。摄影机位置曲线、注视和焦距分开计算。

`cgShotSkills.ts` 注册后侧/侧面跟拍、固定高位全景、移动情绪、双人对话、越肩、反应特写、交互侧拍等配方。候选依据行为、叙事目的、参与者和几何可拍性筛选。已有手工机位保持精确；普通构图编辑会标记 authored-intent，不能被其他技能静默覆盖。自动对话候选检查相邻镜头的互动轴线侧别，明确 reestablish 可重建空间关系。

## 编辑、同步和确认

工作区的“已求解的演出行为”可选择行为进行局部精修，镜头仍可独立选择。行为时间只引用其他行为，镜头时长改变不会修改行为时刻。镜头未覆盖完整演出时给出诊断，不能为消除错误而重新计时演员。

自动覆盖槽位带 autoDuration，行为节奏变化后按对应行为结束事件重新计算镜头时长；镜头方案与人物动作仍是独立数据。明确修改镜头时长会转为人工时长模式，优先保留人工时长锁，无法兼容时返回冲突。道路步态在起步和停步的短窗口与静止姿态渐变，人物与摄影机都读取相同的混合姿态。

map_guide / map_seat anchor 携带语义 binding，地图同步后重新解析。无 binding 的用户世界坐标保持精确。目标删除、旧模型动画、接触失效或路线冲突留下诊断，旧 confirmed 不被覆盖。

仅 performance 阶段的产物不能确认。完整候选通过原有 revision/compileId/inputHash 比较后才可 Confirm。导出包含冻结地图、模型、动画、根轨迹、镜头、事件与占用，不依赖播放时再次调用 AI。

新 V2 摄影机保存 30Hz 完整机位样本，播放直接采样冻结结果，末尾非整帧时间单独处理。人工机位始终精确；带人工控制点的路径保持原曲线，不因烘焙采样错过控制点。固定镜头的语义参照优先使用关联行为开始时刻，避免坐下前转身阶段使“侧拍”参照错误。候选先满足全部可行性门槛，再按可见性质量排序。

V2 预览使用固定 16:9 画幅，窗口比例变化时留边，确保编译观察与实际预览的投影一致。V1 预览保留原尺寸行为。路线叠加层显示完整求解轨迹；自动摄影机仍只暴露起点、中间点、终点三个初始编辑控制点。

## 验收入口

CG 工作区“基础闭环演示 · 跑步、对话、坐下”创建一个独立的、明确标记为内置演示的 CG 项目。它不修改当前 WorldForge 地图，也不会作为远程生成失败的替代。HTTP 入口为 `POST /api/cg/foundation-demo`，后续沿用 projects 的 compile/confirm/export/reopen API。

专门回归测试：cgFoundation.test.ts、cgSpatialPipeline.test.ts、cgServer.test.ts。全量测试、构建、verify:worldforge 和浏览器验收共同检查基础闭环；真实外部 AI 输出质量及任意生成模型的接触适配仍须逐次验证。

### 2026-09-14 验收记录

- 824 项全量测试通过，生产构建、WorldForge 基线边界检查通过；纯净 worldforge-studio 工作区无修改。
- 浏览器使用独立基础场景验证沿路运动、双人对话、坐下、持续坐姿和动态特写；单击选择动线、双击进入控制点编辑均可用。
- 将跑步从 6 秒改为 7.5 秒后，自动镜头覆盖与后续行为事件同步更新，行为总长 15.5 秒。再单独延长最后镜头，只更新一个镜头依赖节点，演出行为仍为 15.5 秒，播放总长为 16.125 秒。
- 确认并从导出 API 回读的版本为 cgcreator-2.0.3 / DirectorDocument V2，含 4 条冻结摄影机轨道与 1 个座位占用记录，validation.valid=true。
- 两阶段 AI 调用、越权响应拒绝与失败回滚使用注入响应做自动化验证。本轮没有调用真实远程 AI 重新生成模型或动画；内置校准模型是明确标记的演示资源。
